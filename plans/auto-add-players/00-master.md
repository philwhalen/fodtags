# Feature — Auto-Add New Players + Streamlined Confirmation — Master Plan

Spec: amended in this feature's Specify stage — [`specs/03`](../../specs/03-Data-Ingestion-and-PDGA.md) §3.5/§3.6 (core), [`specs/02`](../../specs/02-Domain-Model-and-Scoring.md) §2.1/§2.2/§2.3/§2.6, [`specs/10`](../../specs/10-Admin-Console.md) §10.2/§10.4, with cross-reference updates in [`00` §5](../../specs/00-Master-Spec.md), [`04` §4.4](../../specs/04-Feature-Leaderboards.md), [`05` §5.3](../../specs/05-Feature-Rounds-and-Ratings.md), [`08` §8.1–§8.6](../../specs/08-Feature-Player-Profiles.md).

## The change in one paragraph

Today an unmatched PDGA entrant sits inert in a review queue and scores nothing until a director types a full holder record. The new behavior: a **brand-new entrant** (has a PDGA #, matches **zero** holders by number **and** by name) is **auto-added as a provisional tag holder** on the next refresh — seeded from the scrape (PDGA #, name, entry date = first round, rating seed, `pdgaMembership = true`, **pool A**, **no tag number**, `confirmed = false`). Provisional holders **score immediately, flagged pending**. The review queue becomes a **streamlined confirmation screen**: confirm (set pool + optional tag number), merge into an existing holder, or exclude as a non-holder. **Ambiguous** (2+ name matches) and **PDGA-less** entrants are *not* auto-added and keep the existing link-decision flow.

## Context: what already exists

- **Matching is pure & already classifies.** `src/server/ingestion/match.ts` (`match()`) returns `matched` / `unmatched` (reasons `ambiguous` | `no-name-match` | `no-pdga-number-match`) / `autoLinks`. It has no DB access — correct place to *classify* an auto-add candidate, wrong place to *create* one.
- **The pipeline is the only impure ingestion seam.** `src/server/ingestion/pipeline.ts` loads `holders` + `stickyMap` **once**, loops sources, calls `match()` → `persistEvent()` → upserts `autoLinks`, then `recompute()` + atomic publish. This is where auto-add creation belongs.
- **Persist attributes by entrant object identity.** `persistEvent` (`persist.ts`) maps `matchResult.matched` (entrant object → holderId) onto `event_results.holderId`. Adding provisional holders to `matched` before persist is enough to attribute their rounds.
- **Review queue reads `event_results`, not `match()`.** `listPendingForQueue` (`playerMatches.ts`) surfaces rows where `holderId IS NULL AND pdgaNumber IS NOT NULL`, deduped by PDGA #, with name-match suggestions. After auto-add, those rows get a holderId and drop out automatically; ambiguous rows (holderId still null) remain.
- **Admin surface.** `src/app/admin/matches/page.tsx` + `match-forms.tsx` (client) + `src/app/admin/actions.ts` → `src/server/admin/mutations.ts` (`linkEntrant`, `createHolderForEntrant`, `markNonHolder`, roster CRUD). Every mutation audits + `commitAndPublish`.
- **Read model & public.** `players-build.ts` emits the `players` index + per-holder profile; `build.ts` `pendingReview = countPending()` feeds the "N pending review" banner on every standings payload. Canonical slug via `buildCanonicalSlugs` (`-{tagNumber}` on collision). Profile header + roster index render eligibility text badges.

## Key architectural decisions (Plan stage)

1. **`tagNumber` becomes nullable; `confirmed` is added — everything else keys off these two columns.** One migration on `tag_holders`. Unique index on `(seasonYear, tagNumber)` already treats NULLs as distinct in SQLite, so multiple tagless holders coexist; app-level uniqueness stays "unique **when present**."
2. **Null tag number = "sorts last" via a single comparator key.** Introduce a pure `tagSortKey(tagNumber): number` (`null → Number.MAX_SAFE_INTEGER`) with **holder ID as the deterministic secondary** for ties among tagless holders. Every existing `a.tagNumber - b.tagNumber` tie-break (engine `standings.ts`/`season.ts`, `players-build`, `skins-build`, `rounds-build`, `score-sheet-build`) routes through it. The engine stays pure — this is a comparator change, not new computation.
3. **Auto-add lives entirely in the pipeline, keyed by PDGA #.** `match()` gains an `autoAdds` bucket (the old `no-name-match` case: has PDGA #, zero name hits); `unmatched` narrows to `ambiguous` + `no-pdga-number-match`. The pipeline groups auto-adds by PDGA #, creates one provisional holder each (entry date = earliest round date in that source; rating seed = reported player rating), attributes **every** matching entrant object, records a sticky **auto** match + a **system** audit row, and — critically — **injects the new holders into the in-run `holders` list and `stickyMap`** so a player appearing in a second source the same run auto-links instead of duplicating.
4. **The queue is redefined as two lists, not rebuilt.** `countPending` = provisional-unconfirmed holders **+** ambiguous link-decisions. New repo reads (`listProvisionalHolders`) and mutations (`confirmHolder`, `mergeProvisionalIntoHolder`, extend `markNonHolder` to retire a provisional record). Legacy `linkEntrant` / `createHolderForEntrant` / `markNonHolder` stay for the ambiguous/PDGA-less list.
5. **"Pending confirmation" is a read-model flag, rendered as a text badge.** `players` index + profile payload carry `provisional: boolean` and nullable `tagNumber`; the roster row and profile header render a **"Pending confirmation"** badge and **"—"** for a missing tag number. The public banner wording generalizes to "N players pending review."

## Decisions locked (Specify stage — from user answers)

- **Provisional holders score immediately, flagged pending** (not gated). The pending badge + banner are the only guardrails; user accepted their effect on standings/OLP/skins/financials.
- **Guests exist → "exclude (non-holder)" stays**; auto-add is opt-out.
- **Tag number nullable, sorts last**; ties among tagless holders → holder ID.
- **No-PDGA# entrants → manual queue "as today"** (i.e. remain excluded-from-points minimal records; surfacing no-PDGA# rows in the queue is explicitly out of scope, matching current behavior where the queue filters `pdgaNumber IS NOT NULL`).
- **Confirm requires pool, tag number optional**; `pdgaMembership` seeded `true`; entry date = first ingested round (director corrects if the real purchase was later).

## Non-negotiables carried from CLAUDE.md / spec 12

- **Engine stays pure.** No I/O, clock, or DB in `src/server/engine/`. The tie-break change is a pure comparator; provisional-holder *creation* happens only in the ingestion layer (`pipeline.ts`).
- **Public reads only the read model.** No recompute/PDGA on the request path; provisional flag + null tag flow through published payloads.
- **Atomic publish preserved.** Auto-add writes happen inside the refresh before `recompute()` + the single publish transaction; a failed run never leaves half-created holders visible (per-source persist is already transactional; provisional creation is part of the same run).
- **Sticky & idempotent.** Re-running a refresh never re-creates or re-queues a resolved entrant (auto-add, confirm, merge, link, non-holder all sticky by PDGA #).
- **Auditable.** Auto-add records a `system` audit row; every director action audits who/what/before/after as today.

## Test strategy

- **Pure first:** `tagSortKey` + `match()` classification are table-driven Vitest — the load-bearing logic (null-last ordering, auto-add vs link classification) is verified without a DB.
- **Pipeline correctness:** dedicated ingestion test for the **cross-source single-run duplicate** hazard (decision 3) and the **sticky no-re-create** invariant on re-run — the two ways auto-add can go wrong.
- **Mutation/queue:** isolated season years (existing 209x pattern) — seed provisional + ambiguous, exercise confirm/merge/exclude, assert `event_results` re-pointing and `countPending`.
- **Reconciliation guard:** re-run the existing engine acceptance + real-2026 reconciliation tests after 02 to prove the comparator change is behavior-preserving for numbered holders.
- **Full gate** each chunk: `npm run typecheck && npm run lint && npm run test`; add `npm run build` on 05 (admin UI) and 06 (public render).
