# Common Work B — Real PDGA Ingestion — Master Plan

**Roadmap item:** [Common Work B](../00-roadmap.md#common-work-b--real-pdga-ingestion) (second post-scaffold block; the biggest technical risk, proven before the feature views).
**Owning specs:** [03 Ingestion & PDGA](../../specs/03-Data-Ingestion-and-PDGA.md) · [10 Admin §10.4/§10.7](../../specs/10-Admin-Console.md) · [12 Architecture §12.7](../../specs/12-Architecture.md)
**Stage 1 decisions (this feature):** record live payloads first → develop against saved fixtures · exact-PDGA# and unique-normalized-name auto-link, only zero/2+ name matches queue · ship header-fetch **and** Playwright fallback in B (`PDGA_SOURCE=stub|live`) · build the monthly official-ratings pull in B (distinct fetch, `official=true` rows).
**Stage 2 decisions (this plan):** built by **sub-agents** (one per sub-plan, Opus-orchestrated, per the user's choice — matching Common A) · live-api is the ingestion surface (not HTML) · one sub-league event = up to 10 rounds = up to 10 League Nights · a single PDGA division per event (`MA1` today); pool is a league overlay applied at match time · official-ratings pull runs its own pipeline entry point, sharing the single-flight guard.

## Goal

Replace the walking skeleton's **stub PDGA source** with the real thing, end to end, so every downstream feature renders **real 2026 league data**: a 403-resilient live-api fetcher (header-fetch primary + Playwright fallback), real `normalize` (raw round payloads → `events` + `event_results`), real player `match` (PDGA#/name → holder, sticky), the **persistence write path** the skeleton never had (ingestion actually writes normalized rows that `computeSeason` then consumes), the **admin matching review queue**, and the **monthly official-ratings pull**. On completion, registering event `104527` and hitting **Refresh now** ingests real rounds and publishes real standings.

This block deliberately does **not** build the four feature views (Features 1–4), the financial engine (Common C), or player profiles (Feature 6).

## The live-api contract (recorded from event 104527, round 7 — the source of truth for sub-plans 01/03/07)

- **Event metadata:** `GET https://www.pdga.com/apps/tournament/live-api/live_results_fetch_event?TournID={id}`
  → `data.Divisions[]` (`DivisionID`, short `Division` e.g. `MA1`, `LatestRound`), `HighestCompletedRound`, `FinalRound` (10), `EndDate`, `DateRange`.
- **Round results:** `GET …/live_results_fetch_round?TournID={id}&Division={MA1}&Round={n}`
  → `data.scores[]`, per entrant. Field mapping into `event_results`:
  | live-api field | normalized / column | notes |
  |---|---|---|
  | `PDGANum` / `HasPDGANum` | `pdgaNumber` | null when `HasPDGANum=0` (guest) |
  | `Name` (`FirstName`/`LastName`) | `displayName` | normalization for name-match: sub-plan 04 |
  | `RoundtoPar` | `rawScoreToPar` | **this round's** score to par (not `ToPar`, which is cumulative) |
  | `RoundRating` | `roundRating` | unofficial per-round rating |
  | `Rating` | `playerRatingReported` | player's current (unofficial) rating |
  | `Completed` + `HasRoundScore` (& round ≤ `HighestCompletedRound`) | `roundFinal` | see sub-plan 03 for exact rule |
  | `RunningPlace`, `Tied`, `WonPlayoff` | context (finish/1st-playoff) | playoff feeds the tournament tie-break the engine currently stubs |
  | `ProfileURL` = `/player/{PDGANum}` | — | the official-ratings source (sub-plan 07) |
- **Headers that returned 200** (no Playwright needed for reads today): browser `User-Agent`, `Accept: application/json`, `Referer: https://www.pdga.com/live/event/{id}/leaders`. Playwright is a genuine *fallback* for when/if this starts 403ing.
- **Attendance is sparse:** a player's `Rounds` string has empty slots for rounds they didn't play → **no result row** for that (event, round). Ingest per (event, round, played-player).

## Non-negotiable boundaries (carry through every sub-plan)

- **Engine stays pure & untouched.** Common B writes only to the normalized store (`events`/`event_results`/`ratings_history`/`player_matches`); it never edits `src/server/engine/`. `computeSeason` already consumes what we persist.
- **All PDGA access is server-only** (`import 'server-only'`), under `src/server/ingestion/`, never in the client bundle. Selected by `PDGA_SOURCE` (`stub` default; `live` opts into network).
- **Manual + scheduled refresh share one pipeline** with the existing single-flight guard; the official-ratings pull shares that guard too. Each run recorded in `refresh_runs`.
- **Atomic publish preserved.** Ingestion writes normalized rows, then the existing `recompute()` builds+flips a new read-model version in one transaction. A per-source failure never publishes garbage (fail-loud on shape change; keep last good snapshot; mark source stale).
- **Idempotent.** Re-running a refresh yields identical stored state (natural-key upserts on `events`/`event_results`), per Spec 03 §3.7.
- **Never silently guess a holder.** Only exact-PDGA# and unique-normalized-name auto-link; everything else queues. Every admin resolution is audited and sticky.

## Acceptance targets (Spec 03/10 — the bar sub-plan 08 must hit)

- A Refresh-now over registered event `104527` (fixture-backed in CI, live in the validation checklist) matches players, recomputes, and publishes atomically — identical to the scheduled path.
- A single source failing leaves other sources' data intact and flags the failure; a malformed payload fails the run and does **not** publish.
- A newly appearing entrant with no confident match lands in the review queue and is excluded from points until resolved; once resolved it stays resolved.
- Every published number is traceable to `(eventSource, round, refreshRun)`.
- Canceling a League Night still zeroes its points everywhere (regression — engine already does this; ingestion must not resurrect canceled rounds).

## Environment / verification notes (carried from Common A)

- The `db:migrate`/`db:seed` tsx scripts don't auto-load `.env` (only Next does) — verification that runs them must `set -a; . ./.env; set +a` first.
- **Do not manually `source` `.env` before `npm run build`** — it sets `NODE_ENV=development`, which collides with `next build` and throws a spurious `useContext` prerender error. Plain `npm run build` (Next loads `.env` itself) is correct.
- **Live network is reachable from this environment** (verified: 200 from `fetch_event`/`fetch_round` for 104527 with browser headers). `PDGA_SOURCE=live` tests are opt-in and **skipped in CI** — CI runs only fixture-backed tests. Be polite: rate-limit, cache raw responses (the pipeline already writes them to `config.rawDir`), re-record fixtures rarely.
