# Feature 4 — Pool Score Sheets — Master Plan

Spec: [`specs/07-Feature-Pool-Score-Sheets.md`](../../specs/07-Feature-Pool-Score-Sheets.md) (amended in this feature's Specify stage) + the scoring/aggregation contract in [`specs/02-Domain-Model-and-Scoring.md` §2.5](../../specs/02-Domain-Model-and-Scoring.md#25-top-n-counts-aggregation)/[§2.4.1](../../specs/02-Domain-Model-and-Scoring.md#241-league-podium--computed-bonus).

## Context: what already exists (Common A/B + Features 1–3)

- **The engine already computes the whole score sheet.** `computeSeason` (`src/server/engine/season.ts`, Stages B–E) produces `results.scoreSheet: Record<holderId, ScoreSheetEntry>`, each entry carrying `byType` ({LeagueNight, Podium, Tournament, FODOpen} counted subtotals), `countedLineItems`, `droppedLineItems` (each with `droppedReason: "cap" | "forfeited"`), and `total`. It also produces `results.championship[pool]` (per-pool ranked `SeasonStandingRow[]`, the ordering/rank/tie-break the sheet reuses) and `results.podium[type]` (`PodiumStanding` with `complete` + top-3-per-pool rows, the source of the **projected** Podium line). **No engine change is needed** — this is a read-only projection like Features 2–3.
- **Read-model publish pipeline is built.** `buildViews(seasonYear)` (`src/server/readmodel/build.ts`) loads the snapshot, runs `computeSeason` once, resolves holder names (`nameById`), and appends per-feature views (championship, sub-league, OLP, rounds meta); `recompute` → `publish` writes a new version + flips `published_pointer` atomically; pages read via `getPublished(season, viewKey)`.
- **Event labels are available** from `listEvents(seasonYear)` (`.label`, `.roundOrdinal`, `.type`) — the same source the Rounds view uses to label rounds.
- **The tournament cap input exists:** `snapshot.tournamentSourceCount` drives best-2 (≤3) vs best-3 (≥4), exactly as the engine derives it internally.
- **Public shell + patterns are built.** `FreshnessHeader`/`StaleBadge`/`PendingReviewBanner`; `standings-table`/`standings-row`/`tie-break-marker` CSS + mobile-card media query; the pool-toggle precedent (`LeaderboardControls`, pool deep links `championship/pool-a|b`); the client name-filter mirrored to `?q=` (`FilterableRoster`); `slugifyName` for name-slug anchors; `getPublished` read path (see `rounds/page.tsx`).

`score-sheet/[pool]/page.tsx` is a `ComingSoon` placeholder today; the nav "Score Sheets" item already points at `/{season}/score-sheet/pool-a`.

## Key architectural decision (Plan stage)

**Score sheets are a read-only projection of existing engine output, enriched with repo-sourced labels/caps — not new computation, not a re-run of the engine.** Mirrors the OLP feature (Feature 3):

- The **per-pool score-sheet views are produced from the single `results`** already computed in `buildViews`, in a dedicated `src/server/readmodel/score-sheet-build.ts` module (given `results` + `nameById` + `tournamentSourceCount`, loading only `listEvents` for labels and the stale signal). One view per pool: `score-sheet/pool-a`, `score-sheet/pool-b` (matching the deep-link granularity, like `championship/pool-*`).
- **Ordering/rank/tie-break come straight from `results.championship[pool]`** (spec §7.2) — the sheet lists exactly that pool's Championship standing, so it lines up 1:1 with the leaderboard and pool-switchers land on their current pool. For each holder the build attaches their `results.scoreSheet[holderId]` line items (label-enriched) plus any **projected Podium** line derived from `results.podium[type]` for incomplete sub-leagues.
- **Display shaping is a pure `src/lib/score-sheet-view.ts` helper** (`projectScoreSheet`): groups counted lines by event type, formats each line's label, derives dropped-reason strings ("beyond best 15" / "beyond best {2|3}" / "forfeited on pool switch"), keeps the projected-Podium line flagged and out of the total, and exposes the caps statement. Client-safe, unit-tested against the **counted-sum === total === leaderboard-total** reconciliation.
- **Public page reads only the published `score-sheet/pool-*` view**, projects it, and renders. Two-level disclosure is native `<details>`/`<summary>` (SSR-friendly, accessible); the name filter is a thin client component over already-projected holders, mirrored to `?q=`.

## Decisions locked (Specify answers + plan follow-ons)

- **Projected Podium shown, flagged, excluded from total** (Specify Q1): derived at build from `results.podium[type]` when `!complete`; rendered as a de-emphasized "projected — not final" line in the expanded detail; **not** part of counted-sum. When the sub-league is marked complete the engine already emits it as a counted `Podium` line (eventId `-1`) — no special-casing needed on that side.
- **Real event labels + date** (Specify Q2): line label = `listEvents` `.label` (+ `roundOrdinal` for League Nights, composed by the pure helper); Podium lines (eventId `-1`) labeled "{SubLeague} Podium". Enrichment is a build-time `eventById` join; the raw `label`/`roundOrdinal` ride on the payload line so the pure helper composes the display string (testable).
- **Championship rank + rank column** (Specify Q3): holders and their order/rank/tie-break flag are `results.championship[pool]`.
- **Two-level disclosure** (Specify Q4): Level 1 = collapsed summary table row per holder; Level 2 = `<details>` expands counted line items; dropped items sit behind a nested `<details>` "show all". Native elements keep it accessible without a client-state machine.
- **No alias route** (plan): unlike OLP/`sub-league`, pools have no "current" notion — nav already deep-links `pool-a`, the toggle emits `pool-a`/`pool-b`. `buildScoreSheetLinks(season)` returns the two hrefs.
- **Caps statement source** (plan): `caps` object on the payload (`leagueNight: 15`, `tournament: 2|3`, `tournamentSourceCount`, `fodOpen: 1`) computed at build from `tournamentSourceCount` (same rule as the engine). The pure helper turns it into the header/label text.
- **0-point counted lines shown as-is** (plan, spec §7.3): no engine annotation for the Pool-B ≥920 case; a 0-point counted line just displays 0.
- **Financials cross-link deferred** (spec §7.4): omitted until Financials ships; no dead link now.

## Non-negotiables carried from CLAUDE.md / spec 12

- **Engine untouched & pure.** No change to `src/server/engine/` or `loadSeasonSnapshot`. The feature only projects existing `SeasonResults` fields (`scoreSheet`, `championship`, `podium`).
- **Public reads only the read model.** Pages call `getPublished(season, "score-sheet/pool-*")`; never read `event_results`/`event_sources` directly. The build edge does the repo reads.
- **Server-only stays server-only.** `score-sheet-build.ts` imports server repositories (`import "server-only"`); the pure projection + payload types live in `src/lib/score-sheet-view.ts` with **no** server imports, so client components/tests can import them.
- **Deep links reproduce the exact view.** `score-sheet/pool-a|b` are stable paths; `?q=` restores the name filter; per-holder `#{name-slug}` anchors are stable.
- **Accessibility** (Spec 11): tie-break, dropped-reason, and projected/not-final carried as **text**, not color alone; disclosure via native `<details>`/`<summary>`; caps stated as real text.

## Test strategy

- **Pure helper first** (`src/lib/score-sheet-view.ts`): table-driven Vitest, no DB/DOM/clock. Carries the correctness weight — the **counted-sum === total** reconciliation (and that the flagged projected-Podium line is excluded from it), dropped-reason derivation for both `cap` (LN best-15 vs tournament best-2/3, cap value from `caps`) and `forfeited`, label composition, per-type grouping/order, and the caps statement text.
- **Build test** extends `src/server/readmodel/build.test.ts` (or a sibling `score-sheet-build.test.ts`): seed holders in both pools with enough League Nights to exceed best-15 (dropped `cap` items), a tournament set crossing the 3→4 boundary (cap 2 vs 3), an incomplete sub-league where a holder is top-3 (projected Podium) then `updateSource(..., {complete:true})` + rebuild (counted Podium), and a pool-switcher (forfeited items) → assert per-pool payloads.
- **Page/integration tests** follow the Feature-1/2/3 precedent (no jsdom/route harness): seed → `recompute`/`publish` → assert the published `score-sheet/pool-*` view and the pure projection the page performs; empty/pre-season; invalid-pool `notFound` via `isValidPool`.
- **Full gate** each chunk: `npm run typecheck && npm run lint && npm run test`, and `npm run build` on chunks that add routes/components.
