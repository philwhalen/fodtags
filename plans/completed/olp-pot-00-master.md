# Feature 3 — OLP Pot — Master Plan

Spec: [`specs/06-Feature-OLP-Pot.md`](../../specs/06-Feature-OLP-Pot.md) (amended in the Specify stage of this feature) and the OLP contract in [`specs/02-Domain-Model-and-Scoring.md` §2.8](../../specs/02-Domain-Model-and-Scoring.md#28-overall-league-performance-olp).

## Context: what already exists (Common A/B + Features 1–2)

- **The engine already computes ALL of OLP.** `computeSeason` (`src/server/engine/season.ts`, Stage F) produces `results.olp[subLeague]` — a `OlpRow[]` ranked by score across both pools, each row carrying `score`, `ratingComponent`, `avgToPar`, `rounds`, `poolWins`, `eligible`, `payout` (top-3 eligible, largest-remainder), `projected`, `tieBrokenByTag` — plus `results.olpPot[subLeague]` (the `$1 × paidEntries` pot). The worked examples (81.3 / 81.4) are already covered by `olp.test.ts` / `season.test.ts` / `acceptance.test.ts`. **No engine change is needed for this feature.**
- **The pure OLP helpers exist:** `olpScore`, `entriesToOlpPot`, `largestRemainderPayout` (`src/server/engine/olp.ts`); `roundToOneDecimal`, `filterRowsByName<T extends {name}>` (`src/lib`).
- **Read-model publish pipeline is built.** `buildViews(seasonYear)` (`src/server/readmodel/build.ts`) already loads the snapshot, runs `computeSeason`, and resolves holder names (`nameById`); `recompute` → `publish` writes a new version and flips `published_pointer` atomically; pages read via `getPublished(seasonYear, viewKey)`.
- **Public shell + patterns are built.** `FreshnessHeader` / `StaleBadge` / `PendingReviewBanner` / `EmptyStandingsState`; `PublicNav` (the **OLP** nav item already exists, pointing at `/{season}/olp/mid`); the segmented-control pattern (`LeaderboardControls`) and the client name-filter pattern (`FilterableStandings` local-only; `FilterableRoster` with `?q=` URL sync); `resolveCurrentSubLeague` / `getCurrentSubLeagueSlug` for "current sub-league"; `resolveAliasTarget` + `/sub-league/page.tsx` as the redirect-alias precedent.

`olp/[league]/page.tsx` is a `ComingSoon` placeholder today; there is no `olp/page.tsx` alias route yet.

## Key architectural decision (Plan stage)

**OLP is a read-only projection of existing engine output — not a new computation, and not a repository join.** This differs from Feature 2 (Rounds), whose per-round data was absent from the engine and had to be assembled from repositories. Here the numbers already exist in `results.olp`/`results.olpPot`. Therefore:

- The **OLP read-model views are built inside the existing `buildViews`**, reusing the `results` and `nameById` it already has (one `olp/<sub-league>` view per sub-league). We do **not** re-run the engine, add a separate build module, or touch `computeSeason` / `loadSeasonSnapshot`.
- The **eligible-only re-ranking, the "Not yet eligible" split, one-decimal display rounding, and the reason strings live in a pure `src/lib/olp-view.ts` helper** (`projectOlp`), client-safe and unit-tested against the 81.3 / 81.4 reconciliation. The engine's `OlpRow.rank` (score-position across all candidates, interleaved) is **not** used for display; `projectOlp` derives display ranks 1..N over eligible rows.
- **Public pages read only the published `olp/<league>` view**, project it with `projectOlp`, and render. The name search (`?q=`) is client-side over already-projected rows.

## Decisions locked (from the Specify stage's four answers + plan follow-ons)

- **Ineligible = separate "Not yet eligible" section** (Specify Q1): ranked table is eligible-only, ranked 1..N (so ranks 1/2/3 map to the 50/30/20 payouts); ineligible players listed below, unranked, with a reason ("N rounds" / "no PDGA"). A 0-round holder appears in neither (engine already omits holders with no rounds in the sub-league).
- **`/2026/olp` redirects to the current sub-league** (Specify Q2), mirroring the `/sub-league` alias; nav "OLP" points at the bare `/olp`.
- **Show the total pot** alongside per-rank payouts (Specify Q3), labeled projected/final.
- **Client-side name filter** mirrored to `?q=` (Specify Q4), reusing `filterRowsByName`, applied to both the ranked table and the not-eligible section, never re-ranking.
- **Reason derivation** (plan): `rounds < 4` → `"{n} round"/"{n} rounds"`; else (ineligible with ≥4 rounds ⇒ membership is the only possible cause) → `"no PDGA"`. Membership is not carried in the payload; it is inferred from `eligible && rounds`.
- **Pot label source** (plan): `projected` from the sub-league's `complete` flag (equivalently `OlpRow.projected`), surfaced on the payload so the page needn't read `event_sources`.
- **`buildOlpLinks(season)`** (plan): a trivial pure href helper (`/{season}/olp/{slug}` per sub-league) so the control is a thin, testable renderer like `LeaderboardControls`.

## Non-negotiables carried from CLAUDE.md / spec 12

- **Engine untouched & pure.** No change to `src/server/engine/` or `loadSeasonSnapshot`. The feature only projects existing `SeasonResults` fields.
- **Public reads only the read model.** Pages call `getPublished(season, "olp/<league>")`; the alias reads only the `sub-leagues` meta view via `getCurrentSubLeagueSlug`. Never read `event_sources`/`event_results` directly.
- **Server-only stays server-only.** The build edge (`build.ts`) imports server repositories; the pure projection + payload types live in `src/lib/` with no server imports, so client components can import them.
- **Deep links reproduce the exact view.** `olp/<league>` is a stable path; `/olp` is a request-time 3xx redirect; `?q=` restores the name filter.
- **Accessibility** (Spec 11): tie-break and eligibility carried as text, not color alone; the not-eligible reason is real text; segmented control uses the same `role="group"` / `aria-current` pattern as `LeaderboardControls`.

## Test strategy

- **Pure helper first** (`src/lib/olp-view.ts`): table-driven Vitest, no DB/DOM/clock. Carries the correctness weight — the four-component reconciliation (`Rating(10%) + Avg to par − Rounds − Pool wins = score`, incl. the 81.3 / 81.4 examples), eligible-only 1..N re-ranking, the eligible/not-eligible split, reason derivation, tie-break passthrough, and the <3 / 0-eligible payout cases.
- **Build test** extends `src/server/readmodel/build.test.ts`: seed a small fixture (holders in both pools, ≥4-round and <4-round players, a no-PDGA player, entry counts) → assert each `olp/<type>` payload: rows with names, `pot` from entry counts, `projected` mirroring `complete`, per-sub-league `stale`, and empty payload when a sub-league has no rounds.
- **Page/integration tests** follow the Feature-1/2 precedent (no jsdom/route harness): seed → `recompute`/`publish` → assert the published `olp/<league>` view and the pure projection the page performs (ranked vs. not-eligible, pot/payout labels). The alias is covered by asserting `getCurrentSubLeagueSlug` resolution + the redirect target string. Client components (`OlpControls`, `FilterableOlp`) stay thin over tested pure helpers.
- **Full gate** each chunk: `npm run typecheck && npm run lint && npm run test`, and `npm run build` on chunks that add routes/components.
