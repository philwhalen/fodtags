## Context: what already exists (Common A/B/C + Features 1–4)

- **The engine already computes the whole financial picture.** `computeSeason` (`src/server/engine/season.ts`, Stage H → `computeFinancials` in `src/server/engine/financial.ts`) produces `results.financials: SeasonFinancials` (`src/lib/season-results.ts`): `funds` (`FundBalancesCents`: reserves, ace, per-sub-league olp, per-pool skins), `totalCashCents`, the chronological `ledger: LedgerEntry[]` (each with `kind`, ET `date`, `sourceRef`, `deltas`, `netCents`, `runningTotalCents`, and league-night `paidEntries`/`aceEntries`, plus expense `category`/`note`, payout/adjustment `note`), `totals` (tagSales/paidEntries/aceEntries), `subLeagueComplete`, `skinsPaidOut`, and `projected`. **No engine change is needed** — this is a read-only projection like Features 2–4.
- **Every link target is derivable purely from `LedgerEntry.deltas`** — a league-night entry carries an `olp:<TYPE>` delta (→ that sub-league's leaderboard), an OLP-payout carries `olp:<TYPE>` (→ `/olp/<type>`), a skins-payout carries `skins:<POOL>` (→ `score-sheet/pool-<x>`). No build-time enrichment or engine change is required to wire the row-source links (Spec 09 §9.3).
- **Money formatting helpers exist and are pure/client-safe:** `formatCents`, `centsToDollars`, `dollarsToCents` in `src/lib/money.ts` (no server import) — reuse for all display.
- **Read-model publish pipeline is built.** `buildViews(seasonYear)` (`src/server/readmodel/build.ts`) loads the snapshot, runs `computeSeason` once, stamps a single `updatedAt`/`pendingReview`, and appends per-feature views; `recompute` → `publish` writes a new version + flips `published_pointer` atomically; pages read via `getPublished(season, viewKey)`. The `ViewRow.payload` union is the extension point (add `PublicFinancialsPayload`).
- **Public shell + patterns are built.** `FreshnessHeader`/`StaleBadge`/`PendingReviewBanner`; the `getPublished` read path + `export const dynamic = "force-dynamic"` + empty/pre-publish branch (see `olp/[league]/page.tsx`); native `<details>`/`<summary>` disclosure (score-sheet precedent); `standings-*`/mobile-card CSS in `public-shell.css`.

`financials/page.tsx` is a `ComingSoon` placeholder today; the nav "Financials" item already points at `/{season}/financials`, and `financials` is still in `placeholderRouteHrefs`.

## Key architectural decision (Plan stage)

**Financials is a read-only projection of the existing `results.financials` (`SeasonFinancials`) — not new computation, not a re-run of the engine.** Mirrors Features 2–4:

- **A single `financials` view** is produced from the `results` already computed in `buildViews`, in a small `src/server/readmodel/financials-build.ts` module: it wraps `results.financials` with the shared `updatedAt`, per-view `stale`, and `pendingReview` into one `PublicFinancialsPayload` `ViewRow` (`viewKey: "financials"`). No per-pool/per-sub-league fan-out — the whole money picture lives on one page (Spec 09 §9.3).
- **All display shaping is a pure `src/lib/financials-view.ts` helper** (`projectFinancials`): formats cents (via `money.ts`), builds the three section models — **summary** (fund-balance rows + total cash + per-fund projected/final label), **pots detail** (skins per pool, OLP per sub-league with 50-30-20 projected/final split mirroring Spec 06, ace pot with opening/rate/wins), and **ledger** (display rows in the engine's chronological order, league-night rows carrying expandable split children and a sub-league link, payout rows carrying their OLP/score-sheet link, others inline). Client-safe, unit-tested against the reconciliation invariants (total cash = Σ funds; running balance = last entry; split children sum to the night's net).
- **Public page reads only the published `financials` view**, projects it, and renders the three stacked sections with stable anchors (`#summary`/`#pots`/`#pots-skins`/`#pots-olp`/`#pots-ace`/`#ledger`) + a `FreshnessHeader`. Ledger night-split disclosure is native `<details>`/`<summary>`.
- **Two-way cross-links** added on the OLP and score-sheet pages (→ `financials#pots-olp` / `#pots-skins`), fulfilling the Specify decision.

## Decisions locked (Specify answers + plan follow-ons)

- **Single scrolling page, stacked sections** (Specify Q1): one `/{season}/financials` route; summary → pots → ledger with in-page anchor links. No sub-routes, no selector.
- **Expand-in-place + link only where a public page exists** (Specify Q2): league-night rows expand to splits **and** link to the sub-league leaderboard; OLP-payout → `/olp/<type>`; skins-payout → `score-sheet/pool-<x>`; tag-sale/expense/ace-win/adjustment/opening = inline detail only. Link targets derived purely from `deltas` (plan follow-on) — no enrichment.
- **Inbound cross-links added in this feature** (Specify Q3): OLP page pot total → `financials#pots-olp`; each score sheet → `financials#pots-skins` (chunk 05).
- **Collapsed nights, no filter, no pagination** (Specify Q4): the whole season renders on one page; league-night rows default collapsed, expand to splits; non-night rows are single lines.
- **Per-fund projected/final** (spec §9.4, plan): OLP per sub-league from `subLeagueComplete`; skins per pool from `skinsPaidOut`; reserves/ace/total from `SeasonFinancials.projected`. Computed in the pure helper from the flags on the payload.
- **League-night row title from date + sub-league** (plan): composed purely (date + the `olp:<type>` delta's sub-league); **no** `listEvents` label enrichment at build — keeps `financials-build.ts` a thin freshness wrapper. (Round-ordinal labels can be added later if wanted; not a launch need.)
- **"How this is calculated" disclosure** (spec §9.3): static text stating the $6 split (280/100/220¢), $1 ace, $20 tag, and the total-cash = Σ funds invariant — lives in the summary component, no data dependency.

## Non-negotiables carried from CLAUDE.md / spec 12

- **Engine untouched & pure.** No change to `src/server/engine/` or `loadSeasonSnapshot`/`computeFinancials`. The feature only projects the existing `results.financials`.
- **Public reads only the read model.** The page calls `getPublished(season, "financials")`; never reads financial tables directly. The build edge does the (already-loaded) `computeSeason` work.
- **Server-only stays server-only.** `financials-build.ts` imports `server-only`; the pure projection + payload types live in `src/lib/financials-view.ts` with **no** server imports, so client components/tests import them freely.
- **Deep links reproduce the exact view.** `/{season}/financials` + the section anchors are stable; the cross-links target those anchors.
- **Accessibility** (Spec 11): projected/final and running balances carried as **text**, not color alone; night-split disclosure via native `<details>`/`<summary>`; the "how calculated" note is real text; the ledger table has proper headers/scope and scrolls inside its own container on mobile.

## Test strategy

- **Pure helper first** (`src/lib/financials-view.ts`): table-driven Vitest, no DB/DOM/clock. Carries the correctness weight — the reconciliation invariants (**total cash = Σ fund balances = last `runningTotalCents`**, night split children sum to that row's `netCents`), per-fund **projected/final** derivation, the **OLP 50-30-20 largest-remainder** split summing to the pot (mirroring Spec 06 / `olp-view`), and **link-href derivation from `deltas`** for each ledger kind (inline-only kinds yield no href).
- **Build test** (`financials-build.test.ts`): seed a season with opening balances, League Nights across all three sub-leagues (varied paid/ace counts), tag-sale batches, OLP + skins + ace payouts, and expenses → `recompute`/`publish` → assert the published `financials` payload's funds, chronological ledger + running balances, totals, and the projected/`subLeagueComplete`/`skinsPaidOut` flags; flip a sub-league `complete` / record a skins payout + rebuild → assert the corresponding flag flips. Empty pre-season → zeroed funds, empty ledger.
- **Page/integration test** follows the Feature-2/3/4 precedent (no jsdom/route harness): seed → `recompute`/`publish` → assert the published `financials` view and the pure projection the page performs (summary/pots/ledger); empty/pre-season path.
- **Real-data reconciliation** (chunk 06): beyond the synthetic seeds, a committed point-in-time fixture extracted from the league Google Sheet drives a reconciliation test asserting the engine reproduces the sheet's own totals (skins **$478/$239**, ace **$111**) to the cent — the first check against real league math. Expected values are a snapshot, refreshed when the fixture is re-extracted.
- **Full gate** each chunk: `npm run typecheck && npm run lint && npm run test`, and `npm run build` on chunks that add routes/components.
